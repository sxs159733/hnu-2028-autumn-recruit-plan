CHAPTER 02

执行流程与输出规范

把一次例行运行拆成可重复的 10 步：抓取 → 校验 → 复查 → 打标 → 排路线 → 出报告。

2.1 / SOP

标准作业流程（10 步）

顺序不可随意调换：先拿全量、再用首页校验、最后才打匹配度。

01
取全量场次

getcareers count=500 带 headers，按 meet_day >= 今天 过滤，按日期 + 时间排序。

02
首页 + /api/career 核对

核对「日期 + 时间 + 教室」；API 与首页不一致时以首页为准。

03
拿全部双选会

/api/jobfairs 含校外场，记下 fair_id。首页看不到校外场。

04
逐个复查参会企业

对每个未开始的 fair_id 调 hr.bysjy.com.cn 取 companies[]；名单分批更新，每次运行都必须复查。

05
实习网申比对

getonlines?recruit_type=实习招聘，与上一轮快照比对新增 / 下架条目。

06
抓高对口场简章

逐个 /detail/career?id=，提取岗位表、薪资、学历、面试间、网申链接。

07
打匹配度

按筛选规则打「高 / 中高 / 中 / 跳过」。

08
按教学楼分组排路线

同楼连场合并成一次出行；跨校区（科创港）标注「单程约 2 小时，只给必去级」。

09
按输出规范写报告

固定 9 章节，文件名带当天日期。

10
交付 + 记忆维护

交付文件，并把「本轮新发现 / 纠错 / 待跟进 / 产出文件名」写入任务记忆，只写高层摘要。

流程里最容易被跳过的一步

第 4 步：名单复查。双选会 companies[] 分批放量， 本轮就出现 49 → 96 家的翻倍。只跑一次会严重低估场次价值。

2.2 / Data pipeline

数据链路：三个域、七类接口

校内就业网负责场次与简章，第三方域负责校外双选会参会名单，最后汇总成一份报告。

2.3 / Report spec

报告输出规范：固定 9 章节

章节顺序固定，便于每天纵向对比；周末与无场次日也要运行。

序章节核心内容要点
1今日概况抓取量、校验结果+ 与上一版相比的 3 个重要更新
2必去 / 高对口活动按时间逐条展开企业简介 · 时间 · 地点 · 匹配度 · 岗位 · 网申 · 路线
3其余校内宣讲会可跳过 / 低优先级清单每条写跳过原因
4实习网申动态2028 届主通道列出对口条目，比对新增 / 下架
5校外双选会时间线企业数 / 对口率窗口内 + 窗口外提前排期
6本周行动清单今天之后 7 天带 checkbox，按教学楼分组排路线
7提效方法本轮新增 2–4 条不复读已沉淀方法
8目标企业库累计表滚动维护企业库与提效方法都在报告里滚动
9数据来源 + 生成时间接口清单与时间戳末尾标注
2.4 / Convention

命名、排版与记忆约定

文件与自动化

  • 报告文件名 湖南大学秋招活动筛选_YYYY-MM-DD.md，写到工作区根目录
  • 例行执行时间：每天 05:10
  • 只发文字不算完成，必须交付文件
  • 金额 / 比例保留两位小数，如 18.00K–20.00K/月、45.83%

记忆维护

  • 只往任务记忆写高层摘要：日期 / 数据源 / 3–5 条关键发现 / 待跟进 / 文件名
  • 绝不写报告正文、完整企业名单或简章全文
  • 累计的企业库与提效方法只在报告里滚动，不另建第二份台账
  • 改规则时同步改自动化 prompt，不要只改本地文件
周末 / 无场次日

也要照常运行，报告简短说明「今日无场次」并给出未来 7 天窗口，不要输出空占位符。
